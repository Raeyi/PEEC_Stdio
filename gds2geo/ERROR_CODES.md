# GDS2GEO 运行错误与退出码

本表描述随包四个程序的实际 CLI 返回值和诊断边界。成功返回 `0`；失败返回非零。诊断主要是带程序名的文本，机器流程应先检查进程退出码，再保留完整输出；没有 Compact 的 `QS-*` 编码、统一 JSON stderr 或 trace_id 合同。

## 四阶段主流程

| 退出码 | 实际范围 | 处理方式 |
| --- | --- | --- |
| `0` | 阶段成功；`--help` / `--version` 正常显示也返回 0 | 检查相应正式输出，再运行下游 |
| `2` | CLI 解析、自动路径设置、输入缺失/初检、工艺导入拒绝，或加载源/目标包时发现无效内容 | 根据具体错误修正配置、输入或配套文件，从必要上游重建 |
| `5` | 主流程执行中异常，包括几何准备、策略/接触约束、锁/路径保护、网格子进程、结构验收、写入或发布失败 | 阅读完整日志；修正实际原因后重跑本阶段，必要时重建上游 |

`5` 是执行失败的合并返回值，不等于磁盘满或权限不足。部分几何/策略拒绝发生在执行阶段，也可能返回 `5`。同样，GDS/工艺错误在四阶段 source 入口通常通过 `2` 或 `5` 返回，不能套用下方兼容 `convert` 的细分码。

## 常见诊断与恢复

| 诊断/场景 | 常见退出码 | 核查与恢复 |
| --- | --- | --- |
| 两处 `gds2geo_setting.json` 同时存在 | `2` | 根目录配置与 `DATA/Setting/` 配置只能保留一处；不要依赖优先级 |
| `invalid ...gds2geo_setting.json` | `2` | 检查 JSON 语法、两个必需字符串、重复/未知字段及路径；相对路径以 EXE 目录为基准 |
| `ambiguous technology inputs` | `2` | `model_info.csv` 与 `model_info.xtf` 只能保留一份 |
| `source requires a regular GDS input...` / 缺少自动工艺输入 | `2` | 无参入口需要 `model.gds` 和唯一工艺文件；其他文件名使用 `source --gds ... --tech ... --output-dir ...` |
| GDS 顶层不唯一、工艺映射或材料输入被拒绝 | `2` 或 `5` | 阅读完整导入报告；明确 `--top-cell`，修正原工艺/材料，不按文件名推断 |
| `missing source model file` | `2` | 先成功运行 `gds2geo`，确保 source 三文件齐全 |
| `invalid source model` / `invalid geometry bundle` | `2` | 检查 GEO、JSON、MATDB 是否来自同一完整生成；损坏或不同代时重跑必要上游 |
| `missing geometry bundle file` | `2` | 先运行 `geo_prepare`；目标输入须包含本目标 GEO、JSON 及准备库 MATDB |
| 输入输出目录相同、文件身份冲突、重定向路径或路径保护失败 | `2` 或 `5` | 使用不同的普通目录，避免用输出覆盖输入、配置或其他受保护文件 |
| 活动目录锁冲突 | `5` | 等待占用该目录的阶段退出；不要在程序运行中删除锁文件 |
| 源/工艺/目标文件在运行期间改变 | `5` | 停止并行改写，保留稳定输入后重跑；不要混用半套产物 |
| 接触、Via、薄片回填、空 EM 或其他几何政策拒绝 | `5` | 按具体诊断检查原几何与工艺；不使用隐式桥、猜测空气或修改摘要规避校验 |
| Gmsh 缺失、版本不符、失败、超时或超过资源预算 | `5` | 保留匹配的 Gmsh 4.11.1，检查子进程输出及资源；程序不会静默换用其他版本 |
| MSH 无效、材料/接触/正体积等结构检查失败 | `5` | 保留失败日志，核查几何及网格；不把旧 MSH 当作本次成功输出 |
| 输出创建、写入或发布失败 | `5` | 核查目录权限、空间、文件占用和路径类型；此码本身不能区分具体系统原因 |

如果 Windows 在进入程序前报告缺少 DLL 或无法启动，应用层尚未运行，不适用上述 CLI 退出码及日志保证。应恢复完整配套运行库，并保持运行包目录结构。

## 显式兼容入口

以下返回值来自 `gds2geo.exe convert` 的状态映射及显式 CLI 顶层异常处理，不是四阶段主流程的统一细分协议：

| 退出码 | 实际含义 |
| --- | --- |
| `2` | `convert` 配置错误或 CLI 用法错误 |
| `3` | `convert` 的 GDS 读取/内容错误 |
| `4` | `convert` 的层级或几何处理错误 |
| `5` | `convert` 输出错误；`import-tech` 执行/发布或热实体导出失败也可能返回此码 |
| `6` | `convert` 内部错误，或 `gds2geo` 显式 CLI 的未分类标准异常 |

当前交付入口没有已分配的 `7` 返回码。已退役的手动 `validate` 命令不随本包提供；未知命令按 CLI 错误返回 `2`。不要将历史文档的 `7` 或旧验证工具当作当前用户接口。

## 日志与旧结果

无参运行日志统一位于运行包 `DATA/runtime/`，文件名分别为 `gds2geo.log`、`geo_prepare.log`、`geo2thermal.log`、`geo2em.log`，每次覆盖本程序上次日志；配置 JSON 无效时也使用此位置。显式调用直接输出到终端；需要持久记录时自行重定向。源导入尝试证据另存于 `DATA/runtime/source-attempts/`；某些输入初检失败发生在尝试目录建立之前，应以控制台/无参日志为准。

本包的程序锁位于 `DATA/runtime/`，数据包共锁按层级存放于 `DATA/runtime/locks/`，例如 `Result/source/.gds2geo-model.lock`。锁文件不是错误标记，运行时不要删除。外部数据的共锁仍按数据目录定位；其规范父目录为便携包根时也归入 `DATA/runtime/`。没有 `DATA/Setting` 布局的旧程序目录保持原 runtime 规则。

失败时保留该阶段上一组可用正式结果，因此看到旧文件并不能证明本次成功。修正原因后重新运行失败阶段，并根据上游变化重跑必要下游。不得混用不同代的 GEO、JSON、MATDB、MSH 或 receipt。
